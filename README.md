# Бот для сбора обедов

Распознаёт фото меню столовой **бесплатно и локально** через Tesseract OCR
(без внешних платных API), рассылает сотрудникам кнопки выбора блюда по
категориям (каждую можно пропустить — например, заказать только салат) и
собирает всё в структурированную сводку прямо в Telegram. Данные хранятся
локально в SQLite внутри контейнера — никакой Google-таблицы.

Салаты/супы/горячее распознаются с фото каждый день. Гарниры и напитки в
этой столовой почти не меняются и на фото оформлены нестандартно (несколько
блюд в одной строке) — OCR там путается, поэтому они заданы вручную в
`config.py` (`DEFAULT_GARNISH`, `DEFAULT_DRINKS`). Если состав гарниров или
напитков в столовой изменится — просто поправьте эти списки.

Защита от ошибок:
- сотрудник в конце видит сводку своего заказа и подтверждает её либо
  начинает заново одной кнопкой;
- `/myorder` в любой момент показывает и позволяет пересобрать заказ;
- устаревшая кнопка (из вчерашнего меню) не запишется — бот попросит начать заново;
- **сверка даты**: если на фото распознана дата и она не совпадает с
  сегодняшней, бот НЕ рассылает меню сотрудникам, а шлёт админам
  предупреждение — вероятно, это не сегодняшнее фото, нужно переслать
  актуальное вручную;
- оригинал фото меню тоже отправляется сотруднику — если OCR где-то
  ошибся в названии, это сразу видно и можно свериться с фото.

## 1. Как бот узнаёт меню

Канал столовой чужой, поэтому основной способ — бот сам проверяет его
открытую веб-версию (`t.me/s/<канал>`, доступна всем без авторизации),
**по будням (Пн–Пт) в заданное время** (`CHECK_HOUR:CHECK_MINUTE`,
по умолчанию 10:00 по `TIMEZONE`). Ни вступать в канал, ни пересылать
фото не нужно.

Это неофициальный способ — Telegram не документирует эту страницу как
API. Если когда-нибудь вёрстка страницы изменится и парсинг перестанет
находить фото — есть запасной вариант: админ пересылает фото боту в
личку (с аккаунта, чей ID указан в `ADMIN_IDS`), дальше всё так же
автоматически — распознавание, сверка даты, рассылка.

## 2. Настройка

### Бот в Telegram
1. Напишите @BotFather → `/newbot` → получите `BOT_TOKEN`.
2. Через @userinfobot узнайте свой Telegram ID → впишите в `ADMIN_IDS`.

### Переменные окружения
```bash
cp .env.example .env
nano .env   # заполнить BOT_TOKEN, SOURCE_CHANNEL, ADMIN_IDS, при необходимости TIMEZONE/CHECK_HOUR
```

Каждый сотрудник один раз пишет боту `/start` в личку — так бот узнаёт его
Telegram ID (имя берёт из профиля Telegram, можно поменять через `/rename`).

## 3. Запуск в Docker на вашем VPS

```bash
docker compose up -d --build
```

Первая сборка образа дольше обычного — ставится Tesseract OCR с русским
языковым пакетом. Данные (`orders.db`, `employees.json`, `today_menu.json`,
`last_channel_photo.txt`, `notifications_enabled.txt`) лежат в `./data`
на хосте — переживают пересборку и обновление образа.

Логи:
```bash
docker compose logs -f
```
В логах видно расписание следующей проверки канала и результат каждой
проверки — удобно для диагностики.

## 4. Команды

- `/start` — регистрация сотрудника.
- `/rename Имя Фамилия` — изменить отображаемое имя.
- `/myorder` — посмотреть и при желании пересобрать сегодняшний заказ.
- `/summary` (только `ADMIN_IDS`) — сводка по блюдам, сумма, кто не ответил.
- `/remind` (только `ADMIN_IDS`) — напомнить тем, кто не ответил.
- `/notify_on` / `/notify_off` (только `ADMIN_IDS`) — включить/выключить
  рассылку меню сотрудникам. Канал при этом бот продолжает проверять и
  сохранять меню — просто никого не беспокоит (удобно на время отпусков,
  праздников и т.п.).

## 5. Качество распознавания

OCR неидеален — редкие артефакты в названиях блюд возможны (например,
незакрытая скобка с составом). Цена распознаётся надёжно почти всегда.
Дата на фото распознаётся отдельно и служит защитой от рассылки
неактуального меню — если её не удалось найти вообще, проверка даты
просто пропускается (не блокирует рассылку).

## 6. Что можно улучшить дальше (без необходимости прямо сейчас)

- Если распознавание даты слишком часто ложно срабатывает/не срабатывает —
  можно донастроить `DATE_RE` в `menu_parser.py` под конкретный формат.
- Если парсинг страницы канала сломается — в логах это будет видно по
  отсутствию находок; на этот случай есть пересылка фото вручную.
